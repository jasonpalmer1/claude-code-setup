Proactive ideation from the operator's OWN inventory — the opposite of reactive /triage. Born from the 2026-07-22 system audit: the idea pipeline was all KILL-side (go-no-go, triage, kill registry); nothing recombined what he already has into ideas shaped to survive his own filters.

Protocol:

1. **Load the kill context FIRST** (never re-derive settled verdicts): `~/projects/GO-NO-GO.md`, `~/projects/BUSINESS-IDEAS-LOG.md`, `~/projects/VENTURE-HUNT-2026-07-01.md`, memory `project_venture_hunt_findings.md`, `decisions_ledger.md`, and the insight files (`insight_rejection_gradient.md`, `insight_unlock_cascades.md`). Delegate these reads to haiku subagents (explicit `model:`), synthesis stays in the main loop.

2. **Load the inventory:** memory `reference_build_registry.md` (reusable solutions + costs already sunk), `hub/board.md` "Live pipeline" section (warm channels — people, not markets), `reference_analytics.md` / latest pulse (live traffic signals), MEMORY.md active projects.

3. **Generate 5–8 recombinations** of inventory × warm channel × live signal. HARD FILTERS — auto-reject, stating which filter fired:
   - **Distribution shape must be publish / inbound / proxy.** Never DM-shaped cold outreach as the engine — rejection-gradient: DM-shaped dies unsent; publish-shaped ships.
   - **Must clear the settled kills.** If it pattern-matches a killed idea, say so and stop unless something MATERIAL changed since the kill (state what).
   - **Screen incumbents first.** "Nobody serves X" has been false three consecutive times (kill-registry lesson) — assume an incumbent exists until verified otherwise.
   - **🚨 A PIVOT IS A NEW IDEA — RE-SCREEN IT (added 2026-07-25, after a live miss).** If the idea
     changes shape mid-run (marketplace → tool, SaaS → content, product → service), every filter
     re-fires on the NEW shape. An incumbent screen run on the original idea proves nothing about
     the replacement. The 2026-07-25 miss: the "AI agent skill marketplace" was screened rigorously
     and correctly killed, then the pivot to a Claude Code cost-audit tool was built and PUBLISHED
     without any screen — `ccusage` (17.4k stars, org-maintained, pushed that same day) already owned
     the category, already solved the exact bug claimed as the differentiator, and Claude Code ships
     a native `/cost` command. Repo was pulled the same day. Screen BEFORE building, never after.
   - **Distribution is the binding constraint** (2026-07-01 sweep) — an idea that adds supply without a distribution edge is dead on arrival.

4. **Score survivors** (warm-channel strength · build cost GIVEN registry reuse · distribution shape · genuine differentiation). Present at most 3, ranked, each with the ONE cheap validation step (a demand test, never a build).

5. **Close the loop:** log all candidates (including rejects, with the filter that killed them) to `BUSINESS-IDEAS-LOG.md` with date. Anything the operator likes → `/triage`, then `/go-no-go`. Never auto-build; the forge produces candidates, the ladder decides.
