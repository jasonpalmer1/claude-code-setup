description: Summarize the current session into the persistent conversation log
---

Write a concise summary of the current session to the conversation log.

Memory dir: `~/.claude/projects/<home-slug>/memory/`

Steps:
0. **⛔ READ THE NEIGHBORS BEFORE WRITING (the operator, 2026-08-15, standing — the other half of step 6).** He asked for the check *before* the write, not only after: *"check the logs before this log."* You cannot pick the right slug, tier, or hook until you know what is already there.
   - `ls -t` the conversations dir and read the last 2-3 entries. If this session **continues** one of them, say so in the log and name the predecessor file — do not write a standalone entry that silently forks the story.
   - Read the index. **Audit it against disk in BOTH directions**: every pointer resolves to a real file, and every file has a pointer. Orphaned logs are invisible to every future session — that is silent data loss. Fix what you can while you are here; for a log you have not read, index it as unsummarized rather than **inventing a hook to make the index look clean**.
   - Check the index's line cap and the project `CLAUDE.md` char cap *before* adding, so you know up front whether this entry forces an archive pass in the same edit.
   - Ask what this entry **supersedes** and archive that one now.
1. Pick a slug from the session's main topic. Build a filename `conversations/YYYY-MM-DD-<slug>.md` using today's absolute date.
2. Write that file — **under 30 lines**. Capture: what was asked, what was done/decided, key file paths touched, and any follow-ups or open threads. Facts worth persisting long-term go into a real memory file instead (and link to it), not here.
2b. **Footer — always, last line of the file:** `<!-- logged-session: <session-id> -->`. **The id is the exact string every hook payload calls `session_id`** — PreToolUse, PreCompact, SessionEnd, all of them agree on this one value. For a normal top-level session that is your own **transcript filename stem** — the newest `.jsonl` in your own `~/.claude/projects/<dir-slug>/`. It is NOT the cost-meter id, NOT a `/tmp/claude-*/…/tasks/<id>/` lineage/tasks-dir id (a lane or a resumed/continued session can see one of these in its own environment or session prose — it looks session-id-shaped and is easy to grab by mistake, but it is a DIFFERENT id from the hook-visible `session_id` and using it silently breaks the footer), and NOT any other id shown in hook output or session prose. When unsure, the fastest real check is: does this id match a `.jsonl` filename under your own `~/.claude/projects/<dir-slug>/`? If not, it is the wrong id. (For an auto-log run it is the just-ended session's transcript filename, same rule.) This is what makes coverage auditable: `session-end-log.sh` greps for it to decide ok vs MISS, `log-coverage.py` reports the number at every session start and flags any footer id that matches no transcript on disk, and `hooks/log-staleness-enforcer.py` (L-0920) uses it live, in-session, to decide whether to block further work. A log without a correct footer counts as unverified. (Added 2026-09-02 — before it, 482 logs carried 26 session ids between them and no one could prove which sessions were logged. Tightened 2026-09-23 after a wrong id slipped through — [[feedback_a_log_footer_must_be_the_transcript_stem]]. Tightened again 2026-09-23, L-0920 lane audit L3/hub audit H3: a live lane's pre-compact stub reported no real log found because the log on disk carried a `/tmp` tasks-dir id instead of the transcript stem.)
    - **Appending to an EXISTING log (continuation of an earlier session's file, per step 0):** the file may already carry an older `<!-- logged-session: <other-id> -->` line for whichever session created or last appended to it. Leave that line exactly as it is — never edit or remove it — and add a NEW footer line for YOUR OWN current `session_id` as the new last line of the file. A file legitimately carries one footer per session that has ever written to it; `find_real_log()` (used by the compact-stub, the staleness enforcer, and PreCompact's real-log writer) matches on any footer line naming the id it is looking for, wherever it sits in the file.
3. Append one line to `conversations_index.md`:
   `- [YYYY-MM-DD <Title>](conversations/YYYY-MM-DD-<slug>.md) — one-line hook`
4. If any durable fact, preference, or correction surfaced this session, save it to the appropriate memory file and add it to `MEMORY.md` — don't bury it only in the log.
5. End the log file with a short **Resume state** section: open threads, exact next steps, and anything mid-flight (running agents, undeployed changes, unpushed commits) — written so a fresh session could pick up cold from it.
5b. **⛔ Then a `## Pickup prompts` section — MANDATORY (the operator, 2026-09-19, verbatim: *"You need to be including prompts for pick up."*).** Resume state describes the situation; a pickup prompt hands over the action. One fenced code block per open thread, second person, pasteable verbatim into a fresh session with ZERO edits. Each names: the repo/worktree to own, the exact branch + sha, what to do, **what NOT to touch** (fences, gated paths, other sessions' lanes), what closes the ticket, and anything needing the operator's explicit go. A dated check gets its own block naming the date and time. A thread blocked on the operator says so rather than reading as runnable. Goes after Resume state, before the `logged-session` footer. Detail: [[feedback_logs_need_pickup_prompts]].
6. **⛔ VERIFY BEFORE YOU CLAIM IT (the operator, 2026-08-15, standing — binds every skill that logs).** Do not report the log written from the fact that you just wrote it. **Look at the disk, and look at the files AROUND yours** — his words: *"Think of it like a file system. You must check the files around it to make sure it's in the right place."*
   - `ls -la` the conversations dir: **your file must exist with today's date AND a timestamp from this session.** Other logs dated today are other sessions' — a neighbour is not your file. (Real miss 2026-08-15: two logs dated today existed, both belonged to other sessions, and the clear was recommended anyway.)
   - Confirm the `conversations_index.md` line actually landed and its link resolves to the file you just wrote.
   - Confirm any memory file from step 4 is on disk — the store is shared across concurrent sessions with no lock, so a successful tool call is not proof it survived ([[feedback_verify_memory_writes]]).
   If a check fails, fix it and re-verify. **Never say "everything is logged" from memory of having done it.**
7. Only after step 6 passes, end your reply with exactly one closing line naming the file, so the operator sees proof and not a promise: `✅ Logged — <filename> on disk, index line resolves. Logged — continuing.` (This command runs at a size threshold or any natural pause, and never asks the operator to /clear — the log must capture full-context state before auto-compact runs, never after; see L-0802 for the exact trigger timing.)

Keep it terse. The log is for "what happened when," not a transcript.
